# 퍼그린 앱

Expo + React Native + TypeScript로 만든 iOS/Android 앱이다. 와이어프레임 v2 1차 화면을 구현하며 **6번 토지 요약·상세(S07)는 제외**한다. 지도와 로드뷰는 **카카오맵 JavaScript API**로 그린다(웹: 페이지에서 바로, 앱: `react-native-webview` 안에서).

## 실행

```sh
npm ci
cp .env.example .env.local
npm run ios                 # 처음 한 번: 네이티브 빌드(development build) 설치
npm start                   # 이후에는 개발 서버만
```

`react-native-webview`는 Expo Go에도 들어 있지만, 팀은 `npm run ios` / `npm run android`로 development build를 설치해 쓴다. iOS 빌드 중 CocoaPods 오류가 나면 `LANG=en_US.UTF-8`을, Android Gradle 오류가 나면 JDK 17(`JAVA_HOME`)을 지정한다.

iOS 시뮬레이터 API 주소는 localhost:8000, Android 에뮬레이터는 10.0.2.2:8000이다. 실제 휴대폰은 EXPO_PUBLIC_API_URL에 접근 가능한 HTTPS 백엔드의 /api/v1 주소를 입력한다. 기존 EXPO_PUBLIC_API_BASE 서버 주소도 지원한다.

웹 미리보기는 별도 터미널에서 `npm run api:dev`와 `npm run web`을 실행한다. 개발 중계는 같은 PC의 백엔드만 사용하고 127.0.0.1:8001에 바인딩한다. 배포 서버에서 사용하지 않는다. 배포된 백엔드로 붙이려면 `PUGURIN_API_TARGET=<백엔드 주소> npm run api:dev`로 실행한다.

외부 http를 막는 네트워크(학교·회사망 등)에서는 `http://localhost:8081`의 지도가 빈 화면이 된다. 카카오 SDK가 http 페이지에서는 지도 본체와 타일도 http로 받기 때문이다. 이때는 위 두 개에 더해 `npm run web:https`를 실행하고 `https://localhost:8443`을 연다. 처음 실행하면 `.cert/`에 자체 서명 인증서를 만들고(openssl 필요), 브라우저가 처음 한 번 인증서 경고를 띄우면 "고급 → 이동"으로 넘긴다. 카카오 콘솔 JavaScript SDK 도메인에 `https://localhost:8443`도 등록해야 한다.

웹 배포는 Netlify가 [`netlify.toml`](./netlify.toml)대로 한다. main에 머지되면 `npm run build:web`으로 `dist/`를 만들어 올린다. 배포 웹은 같은 주소의 `/api/v1`을 부르고, Netlify가 이를 백엔드로 넘긴다(프록시). 그래서 브라우저가 백엔드를 직접 부르지 않아 CORS 설정이 필요 없다. 백엔드에 HTTPS 도메인이 생기면 `netlify.toml`의 프록시 주소만 바꾼다. `EXPO_PUBLIC_*` 값은 빌드할 때 번들에 들어가므로, 카카오 키나 약관 URL은 Netlify 사이트 설정의 환경 변수에 넣고 다시 배포한다.

### 카카오맵 키

1. [카카오 개발자 콘솔](https://developers.kakao.com)에서 앱을 만들고 **JavaScript 키**를 `.env`의 `EXPO_PUBLIC_KAKAO_JS_KEY`에 넣는다.
2. JavaScript SDK 도메인에 지도를 띄울 주소를 등록한다. 로컬 웹은 `http://localhost:8081`(https 개발 중계를 쓰면 `https://localhost:8443`도), 배포 웹은 Netlify 주소.
3. 제품 설정 → 카카오맵 사용 설정을 켠다. 꺼져 있으면 키와 도메인이 맞아도 지도가 뜨지 않는다.
4. 앱은 WebView 문서 주소(`EXPO_PUBLIC_KAKAO_APP_URL`)로 도메인 확인을 받는다. 2번에 등록한 **https** 주소를 넣는다(http 주소면 iOS가 지도 타일을 막는다).

지도 코드는 `src/map/`에 있다. `kakaoRuntime.ts`가 지도·로드뷰를 그리는 JS 런타임이고, 웹(`MapCanvas.web.tsx`)은 이를 페이지에서 바로, 앱(`MapCanvas.tsx`)은 WebView 안에서 실행한다. 마커 글자·색은 `markers.ts`에서 만들어 넘기고, 겹치는 마커는 점으로 줄인다. 일반/위성은 카카오 기본 지도·스카이뷰, 지적도는 카카오 지적편집도를 쓴다. 지도 줌은 `18 - 카카오 레벨`을 화면·API 줌으로 쓴다.

단지 시트의 **로드뷰** 버튼은 단지 좌표에서 100m 안의 가장 가까운 로드뷰를 띄우고, 없으면 "이 위치는 로드뷰가 없어요"를 보여 준다(`src/roadview/`).

## 구현 범위

지도·거래유형·필터·기간·레이어·면적 단위, 검색·최근 검색어, 지역 시트, 단지 3단계 시트·거래 이력, 거래 목록 화면, 용어 목록·검색·팝업·상세·예시 그림, 더보기·기준일·약관 진입점을 제공한다.

백엔드 메인에 없는 지역 거래목록·단지 분석은 API 준비 상태를 표시한다. 백엔드를 추가 구현하거나 프론트에서 통계를 계산하지 않는다. 샘플 데이터는 더보기에서 명시적으로 선택할 때만 사용하며 API 오류를 자동 대체하지 않는다. 2차 로그인·관심·채팅, 광고 SDK 및 실제 약관 원문은 준비 상태다. 지역·단지 통계 API를 연결해 평형별 추이와 실제 지역 비교를 표시한다. 단지 면적 칩은 서버의 평형별 차트를 변경하며 API가 면적 필터를 제공하지 않아 거래이력에는 모든 면적이 나온다.

경매·공매 물건은 거래유형 칩의 **경매**로 본다. 매매 지도에서는 줌 14 이상일 때 지금 고른 유형 탭(아파트·오피스텔·빌라·토지)의 경매 마커가 단지 마커 옆에 함께 나오고(전세·월세에서는 나오지 않고, 가격·면적 필터가 켜져 있으면 숨긴다), 경매를 고르면 경매 마커만 남는다. 마커를 누르면 3단계 경매 시트가 열리고, 단지 시트에는 그 단지에 진행 중인 경매 카드가 붙는다. 경매 목록 화면에서는 정렬과 지분 빼기를 서버 쿼리로 처리하며, `src/state/auction.ts`의 `AUCTION_SERVER_SORT`를 false로 바꾸면 이 칩들을 숨긴다. 감정가 기준 값은 "감정가 {금액}의 N%"(시트·목록)로만 쓰고, 단지 시트의 경매 카드와 지도 마커는 "감정가의 N%"로 쓰며(실거래 비교가 있으면 "실거래보다 N%↓/↑"), 할인율로 표기하지 않으며, 실거래 비교 필드(`recent_trade_*`)가 없거나 null이면 비교 줄을 숨긴다. 배포 서버에 `/auctions`가 없으면(404) 또는 수집 전이면(503 `DATA_NOT_READY`) 매매 지도에는 아무것도 띄우지 않고 경매 탭과 경매 목록 화면에만 "경매 정보를 준비 중이에요"를 안내한다. API 오류를 샘플로 자동 대체하지 않는다(샘플 모드를 직접 켰을 때만 샘플 경매가 나온다).

학교는 레이어 시트의 **학교** 스위치로 켠다. 처음엔 꺼져 있고 지적도 스위치처럼 저장되어(키 `schools`) 한 번 켜면 다음 실행에도 켜져 있다. 줌 14 이상이고 부산 안일 때만 지도 화면 안의 학교를 낱개 마커로 요청하며(`bbox`만 보낸다), 초·중·고·특·기는 색·글자·도형(동그라미·네모·마름모)으로 구분한다. 마커를 누르면 학교 정보 시트가 열리고 "배정 학교(학군)가 아니라 직선거리로 가까운 학교입니다"를 함께 안내한다. 배포 서버에 `/schools`가 없으면(404) 또는 수집 전이면(503 `DATA_NOT_READY`) 마커를 조용히 생략하고, 레이어가 켜져 있을 때만 "학교 정보를 준비 중이에요"를 띄운다.

병원은 레이어 시트의 **병원** 스위치(학교 아래)로 켠다. 학교처럼 처음엔 꺼져 있고 저장된다(키 `hospitals`). 줌 14 이상이고 부산 안일 때만 화면 안의 종합병원·병원·의원을 `/hospitals?bbox=…&tier=general,hospital,clinic`으로 받아, 화면에서 가까운 병원끼리 옅은 원 하나로 묶어 마커 아래에 깔고 가운데에 "병원 N"을 붙인다. 라벨을 누르면 그 원의 병원을 모두 나열한 시트가 열린다. 응답이 500곳(서버 상한)이면 "병원이 많아 일부만 세었어요. 확대하면 정확해져요"를, 404·503이면 "병원 정보를 준비 중이에요"를 띄운다.

`spikes/vworld-map`은 이전 MapLibre 지도 검증용 코드다(#4). 본 앱은 root의 App.tsx에서 시작한다.

## 검증

```sh
npm test
npm run typecheck
npm run build:web
npm run verify:api
npm run verify:ui
npx expo export --platform ios --platform android
```

UI 검증에는 로컬 8081 미리보기와 8001 개발 중계가 필요하다. Playwright Chromium이 설치되어 있어야 하고 필요시 PUGURIN_CHROMIUM_PATH를 지정한다. 현재 검증은 브라우저의 모바일 크기와 네이티브 JS 번들 기준이며 iOS/Android 실기기 설치 검증은 별도다.

상세 API 연결 상태와 실제 응답 검증 결과는 [API 연결 문서](docs/API_INTEGRATION.md)를 참고한다.

## UI·지도 조작 수정

초기 지도는 대한민국 전역으로 시작한다. 지도는 부산 밖으로 이동할 수 있으며, 거래 조회는 화면 안에 들어온 부산 영역만 요청한다. 부산 데이터 지원 안내가 지도를 가리는 팝업으로 계속 남지 않는다.

본문과 아이콘을 축소하고 검색·탭·버튼·필터를 작게 조정했다. 줌 버튼은 정수 줌 단위로 260ms, 검색·마커 이동은 360ms 애니메이션을 적용한다.
